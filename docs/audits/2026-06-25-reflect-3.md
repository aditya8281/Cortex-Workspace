| 1 | quality | action-item | **Feature flag `CORTEX_NEW_AGENT_LOOP` is dead config** — defined in `config.py` but never read by any runtime code. No conditional branch checks `settings.CORTEX_NEW_AGENT_LOOP` anywhere. Progress.md says "✅ Complete" but only the config field exists, not the switching logic. | Either wire it into agent loop dispatch (e.g., `run_manager.py` or `agent_router.py`) or remove it and add when streaming loop is built. | 2 | security | action-item | **Path traversal check in `_ensure_within_workspace` uses `startswith` which can be bypassed.** If `AGENT_WORKSPACE=/workspace`, then `/workspace-extra/file.txt` passes `str(target).startswith(str(workspace))` even though `/workspace-extra` is outside the intended workspace boundary. | Replace with `target.relative_to(workspace)` which raises `ValueError` if target is not under workspace. Apply to both `tool_defs.py` and `security.py` versions. |
| 3 | quality | action-item | **`@tool` decorator wraps sync functions in async wrapper but direct sync call returns coroutine** — `@tool` always returns `async def wrapper(**kwargs)`. Calling a wrapped sync function directly without `await` returns a coroutine object. The `RuntimeWarning: coroutine 'func' was never awaited` fires in test/debug scenarios. | Either: (a) always keep as async (current behavior — document this), (b) inspect func and return sync wrapper for sync tools, or (c) add a `@sync_tool` variant. For now, fix at least the tool that matters: `web_fetch` is sync under the hood (uses `urllib.request`). |
| 4 | quality | action-item | **`web_fetch` has inconsistent return type** — returns `str` on success, `dict[str, str]` on error. LLM function-calling expects a single type. Every error path returns `{"error": msg}` dict. | Normalize return type to always be `str`. Either prefix errors with "Error:" or return JSON-encoded results. |
| 5 | quality | suggestion | **`exec_command` fallback on malformed quoting preserves quote characters** — when `shlex.split(command)` raises `ValueError`, fallback is `command.split()` which produces `['echo', '"hello', 'world"']` with literal quotes. | Return error message on malformed quoting instead of falling back. Add `"Malformed quoting in command"` check. |
| 6 | quality | suggestion | **`tool` decorator wrapper accepts only `**kwargs`** — if a tool is called with positional args, it fails. The schema generation produces object properties so LLMs always use keyword args, but direct imports may pass positional. | Change from `async def wrapper(**kwargs)` to preserve original signature via `@wraps(func)` and explicit param forwarding. Actually `@wraps` already preserves metadata but doesn't change the call signature. Use `inspect.signature` to reconstruct. Low priority. |
| 7 | consistency | suggestion | **`policy.py` `evaluate()` accepts `iteration` param but it's never used** — the method signature has `iteration: int = 0` as a future-proofing hook, but no rule or default_policy uses it. It's dead parameter. | Either use it for iteration-aware policies (e.g., "ask on first use, allow on subsequent") or remove it. Functionally neutral but extra param without consumer is misleading. |
| 8 | test-gap | action-item | **Security tests don't exist** — `security.py` has zero tests for `is_private_url`, `has_blocked_command`, `ensure_within_workspace`. | Add `tests/agents/test_tool_security.py` covering SSRF (public IPs, private IPs, DNS names, metadata endpoints, edge cases), command blocklist (all patterns + safe commands), path traversal (normal paths, with `..`, symlinks, workspace boundary escape). |
| 9 | test-gap | suggestion | **No test for `tool` decorator wrapping sync functions** — `test_tool_decorator_registers` uses `async def` only. | 10 | test-gap | suggestion | **No regression test for the `from __future__ import annotations` + PEP 563 fix** — the fix in `generate_schema` was critical. No test verifies that schema generation works correctly when `from __future__ import annotations` is used. | Add test where a function with `from __future__ import annotations` has `int` param and schema shows `integer` not `string`. |
| 11 | test-gap | suggestion | **`tool_defs.py` tools have no direct tests** — `exec_command`, `git_log`, `git_diff`, `web_fetch`, `ask_user` are tested only through registration. | 18 | consistency | suggestion | **`BLOCKED_COMMANDS` list has some entries with trailing space and some without** — e.g., `"apt "` has trailing space, `"apt-get"` does not, `"yum "` has trailing space, `"dnf "` does. This is fine — `__init__.py` of `tools/` imports everything so all tools register on `from backend.app.agents import tools`. | No action needed. Pattern is correct. |

## Final Verdict

**Overall Quality Score: 7/10**

The core implementation is solid — clean separation, well-tested registry/schema/policy, good security patterns. The critical issues are:
1. A confirmed path traversal bypass (startswith check is trivially bypassable)
2. A dead feature flag marked as complete
3. Zero security test coverage

**Release Readiness: READY WITH FOLLOW-UPS**

The path traversal bypass should be fixed before merge (it's a 5-minute change). The feature flag wiring and web_fetch return type are P1 but not release-blocking. Everything else is P2+.

**Top 5 Priorities:**
1. Fix path traversal bypass in `_ensure_within_workspace` — `startswith` → `relative_to`
2. Wire or remove `CORTEX_NEW_AGENT_LOOP` feature flag
3. Normalize `web_fetch` return type to `str`
4. Update ARCHITECTURE.md agent section
5. Add `test_tool_security.py` with SSRF and path traversal tests
