### Findings

| # | Category | Severity | Finding | Recommendation |
|---|----------|----------|---------|----------------|
| 1 | Security | **action-item** | CSP `_CSP_PROD` has `connect-src 'self'` — blocks WebSocket to `ws://localhost:*` in production | Add `ws://localhost:*` to `_CSP_PROD` or document that WS only works in dev mode |
| 2 | Testing | **action-item** | Zero WebSocket test files — no tests for any of the 6 WS endpoints | Add at least integration tests for `ws_system` and `ws_models` (the two actively used endpoints) |
| 3 | Redundancy | **insight** | `BaseHTTPMiddleware` dispatch-level WS bypasses are redundant — Starlette 1.2.1 bypasses at `__call__` level before `dispatch` is called | Keep as defense-in-depth. Comment explains purpose. |
| 4 | Documentation | **suggestion** | Architecture overview doesn't mention middleware stack or WebSocket endpoints | Add middleware stack section to `docs/architecture/overview.md` listing all 7 middlewares and their WS behavior |
| 5 | Documentation | **suggestion** | No API documentation for WebSocket endpoints (`/ws/system`, `/ws/models`, `/ws/chat`, `/ws/agents`) | Add WebSocket section to `docs/reference/api.md` with connection protocol, auth flow, message formats |
| 6 | Consistency | **suggestion** | Token extraction priority differs: 5 endpoints use (query > protocol > cookie), `ws.py` demo uses (protocol > query, no cookie) | Standardize all endpoints to use the shared `_extract_ws_token` helper |
| 7 | Robustness | **suggestion** | `ws_notifications.py`, `ws_agents.py`, `ws_chat.py` have empty `except Exception: pass` blocks — errors silently swallowed | Add `logger.exception("WS error")` to match `ws.py` demo handler |
| 8 | Architecture | **insight** | `ws_system.py` and `ws_models.py` bypass `ConnectionManager` entirely (raw `ws.send_text`) — intentional for push-only, but inconsistent with chat/agents that use manager | Document the design decision: push-only endpoints use raw WS, bidirectional use ConnectionManager |
| 9 | Frontend | **insight** | `useWebSocket.ts` always uses `ws://` (not `wss://`) — safe for dev, fails in production behind HTTPS | Add protocol detection: `location.protocol === "https:" ? "wss:" : "ws:"` |
| 10 | Frontend | **suggestion** | `agents/page.tsx` WS handler adds new runs with partial data (`input: ""`) — UI shows blank input until next REST fetch | Consider triggering `loadRuns()` when WS detects new run, or fetch that specific run's data |
