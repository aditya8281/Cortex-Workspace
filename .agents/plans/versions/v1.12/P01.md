## Implementation Tasks

### Task 1: Create CodeAnalysis Model

**Architecture:** Code analysis records store per-file analysis results with scores and findings. The `analysis_type` field supports review, security, performance, and complexity analyses. Findings stored as JSON arrays with severity, line number, and message. The `score` field (0-100) enables trend tracking. The `file_hash` field enables cache invalidation.

**DB Schema:**
```sql
CREATE TABLE code_analyses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    owner_id INTEGER NOT NULL REFERENCES users(id),
    file_path VARCHAR(1000) NOT NULL,
    file_hash VARCHAR(64),
    analysis_type VARCHAR(50) NOT NULL,  -- review, security, performance, complexity
    findings JSON DEFAULT '[]',
    suggestions JSON DEFAULT '[]',
    score INTEGER CHECK(score BETWEEN 0 AND 100),
    metadata_ JSON DEFAULT '{}',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_code_analyses_owner ON code_analyses(owner_id);
CREATE INDEX idx_code_analyses_file ON code_analyses(owner_id, file_path);
CREATE INDEX idx_code_analyses_type ON code_analyses(analysis_type, created_at DESC);
```

**File:** `backend/app/models/developer/code_analysis.py`
```python
from sqlalchemy import Column, Integer, String, DateTime, JSON, ForeignKey, Text
from datetime import datetime
from backend.app.db.base import Base


class CodeAnalysis(Base):
    __tablename__ = "code_analyses"

    id = Column(Integer, primary_key=True, autoincrement=True)
    owner_id = Column(Integer, ForeignKey("users.id"), nullable=False, index=True)
    file_path = Column(String(1000), nullable=False)
    file_hash = Column(String(64))
    analysis_type = Column(String(50), nullable=False)
    findings = Column(JSON, default=list)
    suggestions = Column(JSON, default=list)
    score = Column(Integer)
    metadata_ = Column("metadata", JSON, default=dict)
    created_at = Column(DateTime, default=datetime.utcnow)
```

### Task 2: Create RepositoryIntelligence Model

**Architecture:** Repository intelligence tracks overall health scores across multiple dimensions. The `health_score` aggregates complexity, test coverage, documentation, and dependency health. The `dependency_summary` JSON tracks known vulnerabilities and outdated packages. Scores are computed on-demand and cached for 24h.

**DB Schema:**
```sql
CREATE TABLE repo_intelligence (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    owner_id INTEGER NOT NULL REFERENCES users(id),
    repo_path VARCHAR(1000) NOT NULL,
    health_score INTEGER CHECK(health_score BETWEEN 0 AND 100),
    complexity_score INTEGER,
    test_coverage FLOAT,
    documentation_score INTEGER,
    dependencies_count INTEGER,
    issues_found INTEGER,
    dependency_summary JSON DEFAULT '{}',
    analyzed_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_repo_intelligence_owner ON repo_intelligence(owner_id);
CREATE INDEX idx_repo_intelligence_path ON repo_intelligence(owner_id, repo_path);
```

### Task 5: Create CodeReviewFinding Model

**Architecture:** Code review findings store individual review results with confidence scores. Each finding links to a specific analysis session. The `confidence` field (0.0-1.0) tracks AI confidence in the finding. The `fix_suggestion` provides actionable remediation. Findings grouped by severity for dashboard display.

**DB Schema:**
```sql
CREATE TABLE code_review_findings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    owner_id INTEGER NOT NULL REFERENCES users(id),
    analysis_id INTEGER REFERENCES code_analyses(id),
    file_path VARCHAR(1000) NOT NULL,
    line_number INTEGER,
    severity VARCHAR(20) NOT NULL,
    category VARCHAR(100),
    rule VARCHAR(200),
    message TEXT NOT NULL,
    code_snippet TEXT,
    fix_suggestion TEXT,
    confidence FLOAT DEFAULT 0.8,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_code_review_findings_owner ON code_review_findings(owner_id);
CREATE INDEX idx_code_review_findings_severity ON code_review_findings(severity, created_at DESC);
```

### Task 7: Create SkillRegistry Model

**Architecture:** The skill registry manages reusable intelligence components. Skills have version, author, and status tracking. The `skill_config` JSON stores configurable parameters. The `usage_count` and `last_used` fields enable popularity tracking. Skills support composition via the `dependencies` field.

**DB Schema:**
```sql
CREATE TABLE skill_registry (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    owner_id INTEGER NOT NULL REFERENCES users(id),
    skill_name VARCHAR(200) NOT NULL,
    description TEXT,
    version VARCHAR(20) DEFAULT '1.0.0',
    author VARCHAR(200),
    category VARCHAR(100) DEFAULT 'general',
    skill_config JSON DEFAULT '{}',
    dependencies JSON DEFAULT '[]',
    status VARCHAR(20) DEFAULT 'active',  -- active, deprecated, draft
    usage_count INTEGER DEFAULT 0,
    last_used DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_skill_registry_owner ON skill_registry(owner_id);
CREATE INDEX idx_skill_registry_category ON skill_registry(category);
```

## Performance Considerations

- Composite indexes on (owner_id, created_at DESC) for time-range queries
- File hash for cache invalidation avoids re-analysis
- Partial indexes on severity for dashboard queries
- JSON fields indexed for common queries only
