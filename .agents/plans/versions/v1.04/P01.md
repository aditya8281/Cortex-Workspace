## Purpose

Awareness needs structured storage. File changes need timestamps and content hashes for change detection. Repositories need language statistics and dependency lists. Projects need type detection and framework identification. Device info needs hardware and OS details. System health needs service status and response time history. Every downstream awareness service depends on these schemas being correct, complete, and performant.

## Implementation Tasks

### Task 1: Create File Awareness Model

**Architecture:** The file index tracks every file Cortex has indexed. The `content_hash` column (SHA-256) enables change detection: when a file's hash changes, Cortex knows it was modified. The `mime_type` column enables type-based filtering (e.g., "show me all Python files"). The `file_path` column stores the absolute path for direct access.

**File:** `backend/app/models/awareness/file_index.py`

```python
from sqlalchemy import Column, Integer, String, DateTime, BigInteger, Index
from datetime import datetime
from backend.app.db.base import Base


class FileIndex(Base):
    """Indexed file with metadata for change detection."""
    
    __tablename__ = "file_indices"
    
    id = Column(Integer, primary_key=True)
    user_id = Column(Integer, nullable=False, index=True)
    file_path = Column(String(1000), nullable=False)
    file_name = Column(String(255), nullable=False)
    file_extension = Column(String(50), index=True)
    file_size = Column(BigInteger)  # Bytes
    mime_type = Column(String(100))
    last_modified = Column(DateTime)  # Filesystem mtime
    indexed_at = Column(DateTime, default=datetime.utcnow, nullable=False)
    content_hash = Column(String(64))  # SHA-256 for change detection
    parent_directory = Column(String(1000))  # For directory-based queries
    
    __table_args__ = (
        Index("ix_file_user_path", "user_id", "file_path", unique=True),
        Index("ix_file_user_directory", "user_id", "parent_directory"),
        Index("ix_file_user_extension", "user_id", "file_extension"),
        Index("ix_file_content_hash", "content_hash"),
    )
```

**Key Design Decisions:**
- **Unique constraint on `(user_id, file_path)`:** Prevents duplicate indexing of the same file per user.
- **`content_hash`:** SHA-256 hash of file content. Used by `FilesystemWatcherService` to detect changes without reading full content.
- **`parent_directory`:** Enables directory-based queries ("show me all files in /src/").
- **`file_extension`:** Indexed for fast type-based filtering.
- **No FK to users table:** `user_id` is a plain integer, not a foreign key. This avoids cascade delete issues when users are removed.

**Risk Notes:**
- Risk: `file_path` length exceeds 1000 chars on some systems. Mitigation: Symlink resolution before storage. Path truncation with hash suffix for extremely long paths.
- Risk: Binary files have no meaningful content hash. Mitigation: Hash the raw bytes regardless of file type.

### Task 2: Create Repository Awareness Model

**Architecture:** The repository index captures the structural analysis of a code repository. It stores language distribution, framework detection, dependency lists, and code statistics. The `languages` and `dependencies` columns are JSON-encoded strings (not JSONB) for SQLite compatibility.

**File:** `backend/app/models/awareness/repo_index.py`

```python
from sqlalchemy import Column, Integer, String, DateTime, Index
from datetime import datetime
from backend.app.db.base import Base


class RepositoryIndex(Base):
    """Indexed repository with structural analysis."""
    
    __tablename__ = "repository_indices"
    
    id = Column(Integer, primary_key=True)
    user_id = Column(Integer, nullable=False, index=True)
    repo_path = Column(String(1000), nullable=False)
    repo_name = Column(String(255), nullable=False)
    languages = Column(String(500))  # JSON: {"python": 60, "typescript": 40}
    total_files = Column(Integer, default=0)
    total_lines = Column(Integer, default=0)
    last_indexed = Column(DateTime, default=datetime.utcnow, nullable=False)
    framework = Column(String(100))  # Detected primary framework
    dependencies = Column(String(500))  # JSON: package list
    git_branch = Column(String(200))  # Current git branch (if available)
    last_commit_hash = Column(String(40))  # Latest commit SHA
    
    __table_args__ = (
        Index("ix_repo_user_path", "user_id", "repo_path", unique=True),
        Index("ix_repo_user_framework", "user_id", "framework"),
    )
```

**Key Design Decisions:**
- **JSON as String:** `languages` and `dependencies` are stored as JSON strings, not JSONB, for SQLite test compatibility. Application code parses them.
- **Git metadata:** `git_branch` and `last_commit_hash` enable version-aware awareness. Future versions can track commit history.
- **Unique constraint on `(user_id, repo_path)`:** Prevents duplicate repository indexing.

### Task 3: Create Project Awareness Model

**Architecture:** The project index captures project-level metadata. It's similar to the repository index but focused on project type detection (Python, Node, Rust, Go) and framework identification (Next.js, Django, FastAPI). The `configuration` column stores key config values extracted from project files.

**File:** `backend/app/models/awareness/project_index.py`

```python
from sqlalchemy import Column, Integer, String, DateTime, Index
from datetime import datetime
from backend.app.db.base import Base


class ProjectIndex(Base):
    """Indexed project with type and framework detection."""
    
    __tablename__ = "project_indices"
    
    id = Column(Integer, primary_key=True)
    user_id = Column(Integer, nullable=False, index=True)
    project_path = Column(String(1000), nullable=False)
    project_name = Column(String(255), nullable=False)
    project_type = Column(String(100))  # "python", "node", "rust", "go", "unknown"
    frameworks = Column(String(500))  # JSON: ["next.js", "fastapi"]
    configuration = Column(String(500))  # JSON: key config values
    last_scanned = Column(DateTime, default=datetime.utcnow, nullable=False)
    has_tests = Column(Integer, default=0)  # 0 or 1
    has_ci = Column(Integer, default=0)  # 0 or 1 (CI/CD detected)
    has_docker = Column(Integer, default=0)  # 0 or 1
    
    __table_args__ = (
        Index("ix_project_user_path", "user_id", "project_path", unique=True),
        Index("ix_project_user_type", "user_id", "project_type"),
    )
```

**Key Design Decisions:**
- **Boolean as Integer:** `has_tests`, `has_ci`, `has_docker` use Integer (0/1) for SQLite compatibility.
- **`configuration` as JSON string:** Stores extracted config values (e.g., `{"python_version": "3.12", "test_framework": "pytest"}`).
- **Unique constraint on `(user_id, project_path)`:** Prevents duplicate project scanning.

### Task 4: Create Device Awareness Model

**Architecture:** The device info model captures hardware and OS details. It's updated on each check (not real-time monitoring). The `last_checked` field enables staleness detection — if the data is older than 5 minutes, it should be refreshed.

**File:** `backend/app/models/awareness/device_info.py`

```python
from sqlalchemy import Column, Integer, String, DateTime, Index
from datetime import datetime
from backend.app.db.base import Base


class DeviceInfo(Base):
    """Device hardware and OS information."""
    
    __tablename__ = "device_info"
    
    id = Column(Integer, primary_key=True)
    user_id = Column(Integer, nullable=False, index=True)
    hostname = Column(String(255))
    os_type = Column(String(50))  # "linux", "darwin", "windows"
    os_version = Column(String(100))
    cpu_cores = Column(Integer)
    cpu_model = Column(String(255))
    total_memory_gb = Column(Integer)
    available_memory_gb = Column(Integer)
    disk_total_gb = Column(Integer)
    disk_used_gb = Column(Integer)
    python_version = Column(String(50))
    last_checked = Column(DateTime, default=datetime.utcnow, nullable=False)
    
    __table_args__ = (
        Index("ix_device_user", "user_id", unique=True),
    )
```

**Key Design Decisions:**
- **Unique constraint on `user_id`:** Each user has exactly one device info record. Upsert on update.
- **`python_version`:** Useful for project compatibility checks. Detected from `sys.version`.
- **No real-time monitoring:** This is a snapshot, not a streaming metric. Updated on-demand.

### Task 5: Create System Health Model

**Architecture:** The system health model tracks the status of individual services. Each service gets its own row with status, response time, and error message. The `last_check` field enables staleness detection.

**File:** `backend/app/models/awareness/system_health.py`

```python
from sqlalchemy import Column, Integer, String, DateTime, Index
from datetime import datetime
from backend.app.db.base import Base


class SystemHealth(Base):
    """Service health status tracking."""
    
    __tablename__ = "system_health"
    
    id = Column(Integer, primary_key=True)
    service_name = Column(String(100), nullable=False)
    status = Column(String(50), nullable=False)  # "healthy", "degraded", "down"
    last_check = Column(DateTime, default=datetime.utcnow, nullable=False)
    response_time_ms = Column(Integer)
    error_message = Column(String(500))
    check_details = Column(String(500))  # JSON: additional check info
    
    __table_args__ = (
        Index("ix_health_service", "service_name", unique=True),
        Index("ix_health_status", "status"),
    )
```

**Key Design Decisions:**
- **Unique constraint on `service_name`:** Each service has exactly one health record. Upsert on update.
- **`check_details` as JSON string:** Stores additional check info (e.g., `{"db_version": "16.1", "redis_connected": true}`).
- **Status values:** `"healthy"`, `"degraded"`, `"down"` — simple enum, not database enum type for portability.

## Testing Strategy

### Unit Tests

**File:** `tests/test_awareness_models.py`

```python
import pytest
from datetime import datetime
from backend.app.models.awareness.file_index import FileIndex
from backend.app.models.awareness.repo_index import RepositoryIndex
from backend.app.models.awareness.project_index import ProjectIndex
from backend.app.models.awareness.device_info import DeviceInfo

from backend.app.schemas.awareness.file_index import FileIndexResponse, FileChangeSet
from backend.app.schemas.awareness.health import HealthCheckResponse


def test_file_index_creation(db_session):
    """Test creating a file index entry."""
    file = FileIndex(
        user_id=1, file_path="/home/user/project/main.py",
        file_name="main.py", file_extension=".py",
        file_size=1024, mime_type="text/x-python",
        content_hash="abc123", parent_directory="/home/user/project"
    )
    db_session.add(file)
    db_session.commit()
    assert file.id is not None
    assert file.file_name == "main.py"


def test_file_index_user_isolation(db_session):
    """Test that file indices are isolated by user_id."""
    f1 = FileIndex(user_id=1, file_path="/a.py", file_name="a.py")
    f2 = FileIndex(user_id=2, file_path="/a.py", file_name="a.py")
    db_session.add_all([f1, f2])
    db_session.commit()
    
    results = db_session.query(FileIndex).filter(FileIndex.user_id == 1).all()
    assert len(results) == 1


def test_repo_index_creation(db_session):
    """Test creating a repository index."""
```

## Performance Considerations

| Query Pattern | Expected Performance | Index Used |
|--------------|---------------------|------------|
| Get files by user + directory | < 5ms | `ix_file_user_directory` |
| Get files by user + extension | < 5ms | `ix_file_user_extension` |
| Get repo by user + path | < 3ms | `ix_repo_user_path` (unique) |
| Get project by user + type | < 5ms | `ix_project_user_type` |
| Get device by user | < 3ms | `ix_device_user` (unique) |
| Get health by service | < 3ms | `ix_health_service` (unique) |

**Caching Opportunities:**
- Cache device info: Redis TTL 5 minutes (hardware doesn't change often)
- Cache system health: Redis TTL 1 minute (health should be fresh)
- Cache repo stats: Redis TTL 10 minutes

## Cross-Domain Integration

- **Auth Domain:** All models have `user_id` (no FK, but logically scoped). `get_current_user` provides user context.
- **Memory Domain (v1.03):** File changes can trigger episodic memory creation. Repository structure can create semantic memories.
- **Event Domain (v1.02):** File index updates can emit events for downstream consumers.
- **Frontend (v1.04 P04):** Schemas map to API response models. Frontend types generated from OpenAPI.

---

## Security Considerations

- **No secrets stored:** Models store file metadata only, not file content (except hash).
- **User isolation:** Every query includes `user_id` filter.
- **Path validation:** File paths must be absolute and within allowed directories.
- **No binary content:** Binary files indexed by metadata only.
