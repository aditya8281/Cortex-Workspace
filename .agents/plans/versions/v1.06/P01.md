## Implementation Tasks

### Task 1: Create Task Plan Model

**Architecture:** The task plan model represents a decomposed goal as a directed acyclic graph (DAG) of steps. Each step has dependencies (step indices it depends on), a status, and optional tool/params for execution. The DAG structure enables:
- Parallel execution of independent steps
- Dependency-ordered sequential execution
- Partial completion tracking
- Confidence estimation at plan level

**Schema Design:**
```python
# backend/app/models/cognition/task_plan.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Text, Float, Index
from datetime import datetime
from backend.app.db.base import Base


class TaskPlan(Base):
    """DAG-based task plan for goal decomposition.
    
    Steps are stored as a JSON array where each step has:
    - step: int (index, 0-based)
    - description: str
    - status: str (pending, in_progress, completed, failed, skipped)
    - tool: optional str (tool name to execute)
    - params: optional dict (tool parameters)
    - depends_on: optional list[int] (step indices this depends on)
    - result: optional dict (execution result)
    - error: optional str (error message if failed)
    
    Example:
    {
        "steps": [
            {"step": 0, "description": "Gather context", "status": "completed", "depends_on": []},
            {"step": 1, "description": "Analyze data", "status": "in_progress", "depends_on": [0]},
            {"step": 2, "description": "Generate report", "status": "pending", "depends_on": [1]},
        ]
    }
    """
    __tablename__ = "task_plans"

    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, nullable=False, index=True,
                     comment="ID of the user who created the plan")
    goal = Column(Text, nullable=False,
                  comment="High-level goal this plan addresses")
    steps = Column(JSON, nullable=False, default=list,
                   comment="Ordered list of step definitions with dependencies")
    current_step = Column(Integer, default=0,
                          comment="Index of the currently active step")
    status = Column(String(50), default="pending", nullable=False,
                    comment="Plan status: pending, in_progress, completed, failed, cancelled")
    confidence = Column(Float, nullable=True,
                        comment="Estimated confidence 0.0-1.0 in plan success")
    metadata = Column(JSON, nullable=True,
                      comment="Additional plan metadata: decomposition method, LLM model used, etc.")
    created_at = Column(DateTime, default=datetime.utcnow, nullable=False, index=True)
    updated_at = Column(DateTime, onupdate=datetime.utcnow)
    completed_at = Column(DateTime, nullable=True,
                          comment="When all steps completed or plan was cancelled")
    estimated_duration_ms = Column(Integer, nullable=True,
                                   comment="Estimated total execution time in ms")
    actual_duration_ms = Column(Integer, nullable=True,
                                comment="Actual total execution time in ms")

    # Indexes for common queries
    __table_args__ = (
        Index('ix_task_plan_user_status', 'user_id', 'status'),
        Index('ix_task_plan_user_created', 'user_id', 'created_at'),
    )
```

**Performance Considerations:**
- Composite index on `(user_id, status)` for listing active plans
- Composite index on `(user_id, created_at)` for chronological listing
- JSON `steps` column queried by application code, not SQL WHERE — acceptable for plan-level operations
- Steps array size bounded by decomposition depth (typically < 50 steps)

**Risk Note:** JSON `steps` column makes DB-level step queries impossible. If step-level queries become needed, consider a separate `task_plan_steps` table. For now, application-level queries are sufficient.

### Task 2: Create Error Analysis Model

**Architecture:** Error analysis tracks every significant error in the system. Each error is classified by type, analyzed for root cause, and linked to resolution and prevention strategies. The model supports pattern matching by storing error fingerprints (normalized error type + message pattern).

**Schema Design:**
```python
# backend/app/models/cognition/error_analysis.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Text, Float, Index
from datetime import datetime
from backend.app.db.base import Base


class ErrorAnalysis(Base):
    """Error analysis record with root cause determination.
    
    Each record captures:
    - What went wrong (type, message, context)
    - Why it went wrong (root cause analysis)
    - How to fix it (resolution suggestion)
    - How to prevent it (prevention strategy)
    - A fingerprint for pattern matching across errors
    """
    __tablename__ = "error_analyses"

    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, nullable=False, index=True)
    error_type = Column(String(100), nullable=False, index=True,
                        comment="Error class: ValueError, RuntimeError, TimeoutError, etc.")
    error_message = Column(Text, nullable=True,
                           comment="Original error message")
    fingerprint = Column(String(200), nullable=True, index=True,
                         comment="Normalized error pattern for matching: e.g., 'ValueError:invalid_input_*'")
    context = Column(JSON, nullable=True,
                     comment="Error context: module, function, arguments, stack trace summary")
    root_cause = Column(Text, nullable=True,
                        comment="Determined root cause after analysis")
    resolution = Column(Text, nullable=True,
                        comment="Suggested resolution steps")
    prevention = Column(Text, nullable=True,
                        comment="Suggested prevention strategy")
    severity = Column(String(20), default="info",
                      comment="Severity: info, warning, error, critical")
    resolved = Column(Integer, default=0,
                      comment="1=resolved, 0=unresolved")
    resolution_method = Column(String(50), nullable=True,
                               comment="How it was resolved: manual, auto_retry, workaround, ignored")
    related_analysis_id = Column(Integer, nullable=True,
                                 comment="ID of related error analysis if this is a follow-up")
    created_at = Column(DateTime, default=datetime.utcnow, nullable=False, index=True)
    resolved_at = Column(DateTime, nullable=True)

    # Indexes for pattern matching
    __table_args__ = (
        Index('ix_error_user_type', 'user_id', 'error_type'),
        Index('ix_error_fingerprint', 'fingerprint'),
    )
```

**Performance Considerations:**
- Fingerprint index enables fast pattern matching: `GROUP BY fingerprint ORDER BY COUNT(*) DESC`
- Composite index on `(user_id, error_type)` for user-specific error history
- Severity filtering for dashboard: `WHERE severity IN ('error', 'critical')`

### Task 3: Create Hypothesis Model

**Architecture:** Hypotheses represent beliefs or theories that Cortex holds. Each has evidence for and against, a confidence score (0-100), and a lifecycle (active → confirmed/rejected). Hypotheses feed into planning decisions — high-confidence hypotheses can trigger automated actions, while low-confidence ones trigger user confirmation requests.

**Schema Design:**
```python
# backend/app/models/cognition/hypothesis.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Text, Float, Index
from datetime import datetime
from backend.app.db.base import Base


class Hypothesis(Base):
    """Hypothesis with evidence tracking and confidence scoring.
    
    Lifecycle: active → confirmed | rejected
    
    Confidence is recomputed on each evidence change using
    Bayesian updating (see services/cognition/hypothesis.py).
    """
    __tablename__ = "hypotheses"

    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, nullable=False, index=True)
    hypothesis = Column(Text, nullable=False,
                        comment="The hypothesis statement")
    evidence_for = Column(JSON, default=list,
                          comment="List of supporting evidence items: [{text, source, weight, timestamp}]")
    evidence_against = Column(JSON, default=list,
                              comment="List of contradicting evidence items")
    confidence = Column(Float, default=0.5,
                        comment="Confidence score 0.0-1.0, updated via Bayesian reasoning")
    confidence_history = Column(JSON, default=list,
                                comment="History of confidence changes: [{value, timestamp, trigger}]")
    status = Column(String(50), default="active", nullable=False, index=True,
                    comment="Lifecycle: active, confirmed, rejected")
    source = Column(String(100), nullable=True,
                    comment="What triggered this hypothesis: user_input, error_analysis, memory, planning")
    related_plan_id = Column(Integer, nullable=True,
                             comment="ID of related task plan if hypothesis was generated during planning")
    related_hypothesis_id = Column(Integer, nullable=True,
                                   comment="ID of parent hypothesis if this was spawned from another")
    created_at = Column(DateTime, default=datetime.utcnow, nullable=False, index=True)
    updated_at = Column(DateTime, onupdate=datetime.utcnow)
    resolved_at = Column(DateTime, nullable=True,
                         comment="When status changed from active")
    resolution_reason = Column(Text, nullable=True,
                               comment="Why the hypothesis was confirmed or rejected")

    # Indexes
    __table_args__ = (
        Index('ix_hypothesis_user_status', 'user_id', 'status'),
        Index('ix_hypothesis_user_confidence', 'user_id', 'confidence'),
    )
```

### Task 4: Create Tool Execution Model

**Architecture:** Every tool execution is recorded for learning, debugging, and statistics. The model captures the full lifecycle: pending → running → success/failed, with timing, parameters, result, and error details. This is the execution history (E10) that enables the system to learn from past executions.

**Schema Design:**
```python
# backend/app/models/execution/tool_execution.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Text, Float, Index
from datetime import datetime
from backend.app.db.base import Base


class ToolExecution(Base):
    """Complete record of a tool execution attempt.
    
    Captures everything needed for:
    - Debugging failed executions
    - Performance analysis (duration_ms)
    - Learning from past results (result patterns)
    - Security auditing (what tools were called with what params)
    """
    __tablename__ = "tool_executions"

    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, nullable=False, index=True)
    tool_name = Column(String(100), nullable=False, index=True,
                       comment="Name of the tool that was executed")
    parameters = Column(JSON, nullable=True,
                        comment="Input parameters passed to the tool")
    result = Column(JSON, nullable=True,
                    comment="Output result from the tool")
    status = Column(String(50), nullable=False, default="pending", index=True,
                    comment="Execution status: pending, running, success, failed, timeout, blocked")
    started_at = Column(DateTime, default=datetime.utcnow, nullable=False)
    completed_at = Column(DateTime, nullable=True)
    duration_ms = Column(Integer, nullable=True,
                         comment="Execution duration in milliseconds")
    error_message = Column(Text, nullable=True,
                           comment="Error details if execution failed")
    error_type = Column(String(100), nullable=True,
                        comment="Error class if execution failed")
    verification_result = Column(JSON, nullable=True,
                                 comment="Action verifier result: {approved, warnings, errors}")
    retry_count = Column(Integer, default=0,
                         comment="Number of retries attempted")
    parent_execution_id = Column(Integer, nullable=True,
                                 comment="ID of parent execution if this is a retry or sub-execution")
    workflow_id = Column(Integer, nullable=True, index=True,
                         comment="ID of workflow if this execution was part of a workflow")
    metadata = Column(JSON, nullable=True,
                      comment="Additional metadata: sandbox_id, resource_usage, etc.")

    # Indexes for performance analysis
    __table_args__ = (
        Index('ix_tool_exec_user_tool', 'user_id', 'tool_name'),
        Index('ix_tool_exec_status', 'status'),
        Index('ix_tool_exec_workflow', 'workflow_id'),
    )
```

### Task 5: Create Workflow Model

**Architecture:** Workflows chain multiple tool executions into multi-step processes with dependency graphs, conditional branching, and error recovery. The model stores the full workflow definition and runtime state. Workflows are resumable — state is checkpointed after each step.

**Schema Design:**
```python
# backend/app/models/execution/workflow.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Text, Index
from datetime import datetime
from backend.app.db.base import Base


class Workflow(Base):
    """Multi-step workflow with dependency graph and conditional execution.
    
    Steps are stored as a JSON array where each step has:
    - tool: str (tool name to execute)
    - params: dict (tool parameters, can reference previous step results)
    - condition: optional dict ({type: "previous_step_success", step_index: 0})
    - depends_on: optional list[int] (step indices this depends on)
    - status: str (pending, running, completed, failed, skipped)
    - result: optional dict (execution result)
    - error: optional str (error if failed)
    - retry_count: int (number of retries for this step)
    - max_retries: int (maximum retries before failing)
    """
    __tablename__ = "workflows"

    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, nullable=False, index=True)
    name = Column(String(200), nullable=False,
                  comment="Human-readable workflow name")
    description = Column(Text, nullable=True,
                         comment="What this workflow does")
    steps = Column(JSON, nullable=False, default=list,
                   comment="Ordered step definitions with dependencies and conditions")
    status = Column(String(50), default="idle", nullable=False, index=True,
                    comment="Workflow status: idle, running, completed, failed, cancelled, paused")
    current_step = Column(Integer, default=0,
                          comment="Index of the currently executing step")
    created_at = Column(DateTime, default=datetime.utcnow, nullable=False, index=True)
    updated_at = Column(DateTime, onupdate=datetime.utcnow)
    last_run = Column(DateTime, nullable=True,
                      comment="When the workflow was last executed")
    last_run_status = Column(String(50), nullable=True,
                             comment="Status of the last run: completed, failed, cancelled")
    run_count = Column(Integer, default=0,
                       comment="Total number of times this workflow has been run")
    total_duration_ms = Column(Integer, nullable=True,
                               comment="Total execution time of the last run")
    error_message = Column(Text, nullable=True,
                           comment="Error message if last run failed")
    metadata_ = Column("metadata", JSON, nullable=True,
                       comment="Additional workflow metadata: tags, schedule, etc.")

    # Indexes
    __table_args__ = (
        Index('ix_workflow_user_status', 'user_id', 'status'),
        Index('ix_workflow_user_created', 'user_id', 'created_at'),
    )
```

### Task 6: Create Confidence Score Model

**Architecture:** Confidence scores are tracked over time for each reasoning output. This model stores the history of confidence evaluations, enabling trend analysis and calibration. A well-calibrated system's confidence scores should correlate with actual success rates.

**Schema Design:**
```python
# backend/app/models/cognition/confidence_score.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Float, Index
from datetime import datetime
from backend.app.db.base import Base


class ConfidenceScore(Base):
    """Historical record of confidence evaluations.
    
    Each score captures:
    - What was evaluated (task_type, context)
    - What confidence was assigned
    - What factors influenced the score
    - Whether the prediction was accurate (retroactive verification)
    """
    __tablename__ = "confidence_scores"

    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, nullable=False, index=True)
    task_type = Column(String(100), nullable=False, index=True,
                       comment="Type of task: memory_retrieval, planning, error_analysis, etc.")
    confidence = Column(Float, nullable=False,
                        comment="Confidence score 0.0-1.0")
    factors = Column(JSON, nullable=True,
                     comment="Factors that influenced the score: [{key, value, weight}]")
    context = Column(JSON, nullable=True,
                     comment="Task context at time of evaluation")
    actual_outcome = Column(String(50), nullable=True,
                            comment="Actual outcome: success, failure (filled retroactively)")
    was_accurate = Column(Integer, nullable=True,
                          comment="1=confidence matched outcome, 0=miscalibrated")
    source = Column(String(100), nullable=True,
                    comment="What triggered this evaluation: plan, hypothesis, tool_exec")
    related_id = Column(Integer, nullable=True,
                        comment="ID of related entity (plan, hypothesis, execution)")
    created_at = Column(DateTime, default=datetime.utcnow, nullable=False, index=True)

    # Indexes for calibration analysis
    __table_args__ = (
        Index('ix_confidence_task_type', 'task_type'),
        Index('ix_confidence_user_task', 'user_id', 'task_type'),
    )
```

## Security Considerations

1. **JSON steps validation:** Validate step structure on input (no code execution in steps, only tool references)
2. **Workflow tool params:** Sanitize parameters before passing to execution engine (no SQL injection via params)
3. **Hypothesis evidence:** Sanitize evidence text to prevent XSS in UI rendering
4. **Execution result size:** Limit result JSON size to prevent memory issues (10MB max)
5. **Ownership:** All models have `user_id` — all queries must filter by current user

---

## Cross-Domain Integration

- **Memory domain (v1.03):** Plans query memory for context; hypotheses query memory for evidence; error analysis learns from memory patterns
- **File awareness domain (v1.04):** Plans can include file operations; workflows can process files; tool executions operate on files
- **Privacy domain (v1.05):** All operations logged to audit trail; tool executions checked by ActionVerifier (P04); access control gates plan creation
- **Event system (v1.02):** Plan status changes emit events: `plan.created`, `plan.completed`, `plan.failed`; execution events: `tool.started`, `tool.completed`, `tool.failed`
