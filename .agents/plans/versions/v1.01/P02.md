## Objective

Move all backend models from the flat `models/` directory into domain-organized subdirectories. Align model ownership with service ownership from P01.

---

## Purpose

The current `models/` directory contains 18 flat Python files. Models are the source of truth for database schema, yet they have no clear domain ownership. Reorganizing into domain directories:

1. **Aligns with services** — models live in the same domain as the services that use them
2. **Prevents schema sprawl** — new models are placed in the correct domain from the start
3. **Enables domain-specific migrations** — v1.02 can add per-domain migration strategies
4. **Reduces Alembic confusion** — autogenerate scans domain directories, not a flat list

## Implementation Tasks

### Task 1: Create Domain Model Directories

Create the following directories under `backend/app/models/`:

```
backend/app/models/
├── memory/           # Document, Graph, LongTermMemory, PathIndex, StorageRegistry
├── awareness/        # FileIndex, IndexingConfig, RepoIndex
├── intelligence/     # EmbeddingCache, ModelCatalog
├── interaction/      # Conversation, Notification, User
├── cognition/        # Agent
├── privacy/          # AuthEvent, UserSettings
├── integration/      # SyncState
└── system/           # (empty — reserved for future system models)
```

Each gets `__init__.py` that re-exports all models:

```python
# backend/app/models/memory/__init__.py
"""Memory domain models."""

from backend.app.models.memory.document import Document
from backend.app.models.memory.graph import Graph
from backend.app.models.memory.long_term_memory import LongTermMemory
from backend.app.models.memory.path_index import PathIndex
from backend.app.models.memory.storage_registry import StorageRegistry

__all__ = [
    "Document",
    "Graph",
    "LongTermMemory",
    "PathIndex",
    "StorageRegistry",
]
```

**Code architecture:**
- Model `__init__.py` files must import ALL models in the domain for Alembic
- `migrations/env.py` imports from `backend.app.models` which re-exports from domain `__init__.py` files
- No model can import from another domain's models (cross-domain references use foreign keys only)

**Test Criteria:**
- All 8 directories exist with `__init__.py`
- `python -c "from backend.app.models.memory import Document"` works
- `python -c "from backend.app.models.interaction import User"` works
- `python -c "import backend.app.models"` works (all re-exports)

**Risk Notes:**
- *Risk:* Alembic can't find models after move. *Mitigation:* `models/__init__.py` re-exports all models. Alembic imports from `backend.app.models`.
- *Risk:* Model relationships break. *Mitigation:* SQLAlchemy relationships use string references (`User.id`), not direct imports. Moving files doesn't break relationship definitions.

### Task 5: Verify Circular Import Prevention

Run comprehensive circular import checks.

**Verification steps:**

```bash
# Check 1: Basic import
python -c "import backend.app.models"
echo "Basic import: $?"

# Check 2: Each domain imports independently
for domain in memory awareness intelligence interaction cognition privacy integration; do
  python -c "from backend.app.models.$domain import *"
  echo "$domain: $?"
done

# Check 3: Cross-domain import check (should fail or be explicitly allowed)
python -c "from backend.app.models.memory import Document; from backend.app.models.interaction import User; print('Cross-domain OK')"
echo "Cross-domain: $?"

# Check 4: Full application import
python -c "from backend.app.main import app"
echo "App import: $?"

# Check 5: Circular import detector
python -c "
import sys
import importlib
models = ['memory', 'awareness', 'intelligence', 'interaction', 'cognition', 'privacy', 'integration']
for m in models:
    try:
        importlib.import_module(f'backend.app.models.{m}')
        print(f'{m}: OK')
    except ImportError as e:
        print(f'{m}: FAILED - {e}')
"
```

**Test Criteria:**
- All domain imports work independently
- Cross-domain imports work (via re-exports)
- Full application imports work
- No circular import errors

**Risk Notes:**
- *Risk:* Circular imports exist but aren't detected by basic checks. *Mitigation:* Full application import test catches deep circular dependencies.
- *Risk:* Circular imports are introduced later. *Mitigation:* CI can add circular import detection as a gate.
