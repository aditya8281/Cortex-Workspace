## Implementation Tasks

### Task 1: Create Audit Log Model

**Architecture:** The audit log is the backbone of the trust system. Every significant action across all domains (memory, files, settings, agents, workflows) flows through this model. It must be immutable — once written, rows are never updated or deleted in normal operation.

**Schema Design:**
```python
# backend/app/models/privacy/audit_log.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Text, Index
from sqlalchemy.orm import relationship
from datetime import datetime
from backend.app.db.base import Base


class AuditLog(Base):
    """Immutable audit trail for all significant system actions.
    
    This model is append-only. No UPDATE or DELETE operations are permitted
    in application code. Retention policies are enforced by scheduled jobs.
    """
    __tablename__ = "audit_logs"

    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, nullable=False, index=True, 
                     comment="ID of the user performing the action")
    action = Column(String(100), nullable=False,
                    comment="Action type: create, read, update, delete, login, logout, consent_grant, consent_revoke, export, access_check")
    resource_type = Column(String(100), nullable=False, index=True,
                           comment="Resource domain: memory, file, settings, agent, workflow, consent, audit")
    resource_id = Column(Integer, nullable=True, index=True,
                         comment="ID of the affected resource, NULL for non-resource actions")
    details = Column(JSON, nullable=True,
                     comment="Structured context: old_value, new_value, metadata")
    ip_address = Column(String(50), nullable=True,
                        comment="Client IP at time of action")
    user_agent = Column(String(500), nullable=True,
                        comment="Client user agent string")
    session_id = Column(String(200), nullable=True,
                        comment="Session identifier for correlating related actions")
    timestamp = Column(DateTime, default=datetime.utcnow, nullable=False, index=True,
                       comment="UTC timestamp of action")
    success = Column(Integer, default=1, nullable=False,
                     comment="1=success, 0=failure")
    error_message = Column(Text, nullable=True,
                           comment="Error details if action failed")
    duration_ms = Column(Integer, nullable=True,
                         comment="Action duration in milliseconds for performance tracking")

    # Composite indexes for common query patterns
    __table_args__ = (
        Index('ix_audit_user_timestamp', 'user_id', 'timestamp', postgresql_using='btree'),
        Index('ix_audit_resource_timestamp', 'resource_type', 'resource_id', 'timestamp', postgresql_using='btree'),
        Index('ix_audit_action_timestamp', 'action', 'timestamp', postgresql_using='btree'),
    )
```

**Performance Considerations:**
- Composite index on `(user_id, timestamp)` for user activity queries (most common)
- Composite index on `(resource_type, resource_id, timestamp)` for resource history queries
- Index on `action` for filtering by action type in dashboards
- Table is append-only — no update locks, high write throughput
- Consider partitioning by month when table exceeds 10M rows

**Risk Note:** Unbounded growth. Mitigated in P03 with retention policy service.

### Task 2: Create Consent Record Model

**Architecture:** Consent records are the gating mechanism for all data access. Every service that reads user data must check consent first. The model tracks the full lifecycle: grant → active → expiry/revocation. Consent is scoped to specific data categories and can have time-based expiry.

**Schema Design:**
```python
# backend/app/models/privacy/consent.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Text, Index, Boolean
from datetime import datetime
from backend.app.db.base import Base


class ConsentRecord(Base):
    """Granular consent record for user data access control.
    
    Each record represents a user's explicit decision about a specific
    data category. Consent can be granted, revoked, and can expire.
    The access control service checks these records before any data access.
    """
    __tablename__ = "consent_records"

    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, nullable=False, index=True,
                     comment="ID of the user granting/denying consent")
    consent_type = Column(String(100), nullable=False,
                          comment="Data category: memory_read, memory_write, file_read, file_write, agent_execution, analytics, third_party")
    granted = Column(Integer, nullable=False,
                     comment="1=granted, 0=denied/revoked")
    scope = Column(String(200), nullable=True,
                   comment="Specific scope: e.g., 'user_files', 'memories', 'all'")
    context = Column(JSON, nullable=True,
                     comment="Additional context: why consent was requested, what it enables")
    created_at = Column(DateTime, default=datetime.utcnow, nullable=False, index=True)
    expires_at = Column(DateTime, nullable=True,
                        comment="Optional expiration; NULL means no expiry")
    revoked_at = Column(DateTime, nullable=True,
                        comment="Timestamp when consent was revoked")
    revoked_reason = Column(String(500), nullable=True,
                            comment="Optional reason for revocation")
    version = Column(Integer, default=1, nullable=False,
                     comment="Consent version for detecting stale consent")

    # Unique constraint: one active consent per user per type
    __table_args__ = (
        Index('ix_consent_user_type', 'user_id', 'consent_type', unique=True),
        Index('ix_consent_active', 'user_id', 'granted', 'expires_at'),
    )
```

**Performance Considerations:**
- Unique index on `(user_id, consent_type)` ensures fast lookup for access checks
- Composite index on `(user_id, granted, expires_at)` for "active consents" query
- Consent checks are on the critical path for every data access — must be fast
- Cache active consents in Redis with 5-minute TTL; invalidate on grant/revoke

**Risk Note:** Consent inconsistency if cache and DB diverge. Mitigated by event-driven invalidation in P02.

### Task 3: Create Data Export Model

**Architecture:** Data export enables data portability (GDPR Article 20). Users can request a complete export of all their data in standard formats. Exports are processed asynchronously — the model tracks the full lifecycle: pending → processing → complete/failed. File paths are stored for download, with automatic cleanup after expiry.

**Schema Design:**
```python
# backend/app/models/privacy/data_export.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Text
from datetime import datetime
from backend.app.db.base import Base


class DataExport(Base):
    """Data export request tracking.
    
    Users can request exports of all their data. Exports are processed
    asynchronously and stored as downloadable files. Files are cleaned
    up after a configurable retention period.
    """
    __tablename__ = "data_exports"

    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, nullable=False, index=True,
                     comment="ID of the requesting user")
    export_type = Column(String(50), nullable=False,
                         comment="Export scope: full (all data), partial (specific types)")
    data_types = Column(JSON, nullable=True,
                        comment="List of specific data types for partial exports: ['memory', 'files', 'settings']")
    format = Column(String(20), nullable=False,
                    comment="Export format: json, csv")
    status = Column(String(20), nullable=False, default="pending",
                    comment="Export status: pending, processing, complete, failed")
    file_path = Column(String(1000), nullable=True,
                       comment="Path to the generated export file")
    file_size_bytes = Column(Integer, nullable=True,
                             comment="Size of the exported file in bytes")
    checksum_sha256 = Column(String(64), nullable=True,
                             comment="SHA-256 checksum for integrity verification")
    error_message = Column(Text, nullable=True,
                           comment="Error details if export failed")
    created_at = Column(DateTime, default=datetime.utcnow, nullable=False)
    started_at = Column(DateTime, nullable=True,
                        comment="When processing began")
    completed_at = Column(DateTime, nullable=True,
                          comment="When export completed")
    expires_at = Column(DateTime, nullable=True,
                        comment="When the export file will be deleted")
```

### Task 4: Create Access Policy Model

**Architecture:** Access policies implement ABAC (Attribute-Based Access Control) alongside RBAC. Policies are rules that evaluate against request context (user role, resource owner, time of day, consent state). The policy engine evaluates a set of policies for each access request and returns allow/deny.

**Schema Design:**
```python
# backend/app/models/privacy/access_policy.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Boolean, Text
from datetime import datetime
from backend.app.db.base import Base


class AccessPolicy(Base):
    """Attribute-based access control policy.
    
    Policies define rules for resource access. Each policy specifies:
    - A resource type it applies to
    - An action it governs
    - Conditions that must be met (attribute-based)
    - Effect: allow or deny
    - Priority for conflict resolution (higher wins)
    """
    __tablename__ = "access_policies"

    id = Column(Integer, primary_key=True, autoincrement=True)
    name = Column(String(200), nullable=False, unique=True,
                  comment="Human-readable policy name")
    description = Column(Text, nullable=True,
                         comment="What this policy controls")
    resource_type = Column(String(100), nullable=False,
                           comment="Resource type: memory, file, settings, agent, workflow, * (all)")
    action = Column(String(100), nullable=False,
                    comment="Action: read, write, delete, execute, * (all)")
    effect = Column(String(10), nullable=False,
                    comment="allow or deny")
    conditions = Column(JSON, nullable=False, default={},
                        comment="Attribute conditions: {role: 'admin', owner: true, consent_required: true}")
    priority = Column(Integer, default=0,
                      comment="Higher priority policies evaluated first; deny wins on tie")
    enabled = Column(Boolean, default=True,
                     comment="Whether this policy is active")
    created_at = Column(DateTime, default=datetime.utcnow)
    updated_at = Column(DateTime, onupdate=datetime.utcnow)
```

### Task 5: Create Role and Permission Models

**Architecture:** RBAC foundation. Roles group permissions; users are assigned roles. The system ships with three default roles: admin (full access), user (standard access), viewer (read-only). Permissions are resource-action pairs. This is the simple layer; ABAC policies in Task 4 provide the complex layer.

**Schema Design:**
```python
# backend/app/models/privacy/role.py

from sqlalchemy import Column, Integer, String, DateTime, Table, ForeignKey
from sqlalchemy.orm import relationship
from datetime import datetime
from backend.app.db.base import Base

# Association table for many-to-many user-role relationship
user_roles = Table(
    'user_roles', Base.metadata,
    Column('user_id', Integer, ForeignKey('users.id'), primary_key=True),
    Column('role_id', Integer, ForeignKey('privacy_roles.id'), primary_key=True),
    Column('assigned_at', DateTime, default=datetime.utcnow),
)

# Association table for many-to-many role-permission relationship
role_permissions = Table(
    'role_permissions', Base.metadata,
    Column('role_id', Integer, ForeignKey('privacy_roles.id'), primary_key=True),
    Column('permission_id', Integer, ForeignKey('privacy_permissions.id'), primary_key=True),
)


class Role(Base):
    """Named role that groups permissions."""
    __tablename__ = "privacy_roles"

    id = Column(Integer, primary_key=True, autoincrement=True)
    name = Column(String(50), nullable=False, unique=True,
                  comment="Role name: admin, user, viewer")
    description = Column(String(200), nullable=True)
    created_at = Column(DateTime, default=datetime.utcnow)

    # Relationships
    permissions = relationship("Permission", secondary=role_permissions, backref="roles")


class Permission(Base):
    """Resource-action permission pair."""
    __tablename__ = "privacy_permissions"

    id = Column(Integer, primary_key=True, autoincrement=True)
    resource_type = Column(String(100), nullable=False,
                           comment="Resource: memory, file, settings, agent, workflow, audit, consent")
    action = Column(String(50), nullable=False,
                    comment="Action: create, read, update, delete, execute, export, admin")
    description = Column(String(200), nullable=True)
    created_at = Column(DateTime, default=datetime.utcnow)
```

### Task 6: Create Data Deletion Request Model

**Architecture:** Supports data sovereignty (P6). Users can request deletion of specific data or all data. Deletion is processed asynchronously with cryptographic proof (hash of deleted content stored before deletion). This provides audit trail of what was deleted and when.

**Schema Design:**
```python
# backend/app/models/privacy/data_deletion.py

from sqlalchemy import Column, Integer, String, DateTime, JSON, Text
from datetime import datetime
from backend.app.db.base import Base


class DataDeletionRequest(Base):
    """Tracks data deletion requests for sovereignty compliance.
    
    Enables users to request deletion of specific data categories
    or all data. Provides cryptographic proof of deletion via
    content hashes stored before deletion.
    """
    __tablename__ = "data_deletion_requests"

    id = Column(Integer, primary_key=True, autoincrement=True)
    user_id = Column(Integer, nullable=False, index=True)
    deletion_type = Column(String(50), nullable=False,
                           comment="full (all data), specific (named types)")
    data_types = Column(JSON, nullable=True,
                        comment="Types to delete: ['memory', 'files', 'settings']")
    status = Column(String(20), nullable=False, default="pending",
                    comment="pending, processing, complete, failed")
    items_deleted_count = Column(Integer, default=0,
                                 comment="Number of items deleted")
    deletion_proof_hash = Column(String(64), nullable=True,
                                 comment="SHA-256 hash of deletion manifest for verification")
    error_message = Column(Text, nullable=True)
    created_at = Column(DateTime, default=datetime.utcnow)
    completed_at = Column(DateTime, nullable=True)
```

        consent = ConsentRecord(
            user_id=1, consent_type="memory_read", granted=1, scope="all"
        )
        db_session.add(consent)
        db_session.commit()
        assert consent.id is not None
        assert consent.version == 1

        """Verify one active consent per user per type."""
        c1 = ConsentRecord(user_id=1, consent_type="file_write", granted=1)
        db_session.add(c1)
        db_session.commit()
        # Duplicate should fail
        c2 = ConsentRecord(user_id=1, consent_type="file_write", granted=0)
        db_session.add(c2)
        with pytest.raises(Exception):
            db_session.commit()

    def test_consent_expiry(self, db_session):
        consent = ConsentRecord(
            user_id=1, consent_type="analytics", granted=1,
            expires_at=datetime.utcnow() - timedelta(hours=1)
        )
        db_session.add(consent)
        db_session.commit()
        # Query active consents
        active = db_session.query(ConsentRecord).filter(
            ConsentRecord.user_id == 1,
            ConsentRecord.granted == 1,
            (ConsentRecord.expires_at == None) | (ConsentRecord.expires_at > datetime.utcnow())
        ).all()
        assert len(active) == 0  # Expired consent not in active set

## Security Considerations

1. **Model-level:** No encrypted fields in this phase — encryption is applied in P02 services. Models store plaintext; services encrypt before writing.
2. **Unique constraint on consent:** Prevents duplicate active consent records that could be exploited for privilege escalation.
3. **Audit log immutability:** Application code must never UPDATE or DELETE from `audit_logs`. Enforce with a custom session wrapper in P03.
4. **Role naming:** Reserved role names (`admin`, `user`, `viewer`) should not be deletable. Enforce in P02 service layer.
5. **Deletion request proof:** SHA-256 hash of deletion manifest provides tamper-evident proof of what was deleted.

## Cross-Domain Integration

- **Memory domain (v1.03):** Memory creation checks `consent_type=memory_write`; memory retrieval checks `consent_type=memory_read`
- **File awareness domain (v1.04):** File operations check file_read/file_write consent; file access logged to audit trail
- **Event system (v1.02):** All consent changes emit events: `consent.granted`, `consent.revoked`, `consent.expired`
- **Agent system (v1.01):** Agent actions logged to audit trail; agent permissions checked via RBAC
